============================

Purpose
-------
This report describes the current VaaniPlus English-Hindi speech translation
project. Use the AI IMAGE GENERATION PROMPT below to create a readable system
architecture image. The PlantUML sections can also be rendered as UML diagrams.

Project summary
---------------
VaaniPlus is a local-first web application for English-to-Hindi and
Hindi-to-English translation. Users can translate typed text or record speech.
Speech translation transcribes the recording, translates the transcript, and
generates playable speech. Users can sign in or register and view their five
most recent saved conversions.

AI IMAGE GENERATION PROMPT
--------------------------
Create a polished, landscape software architecture infographic for
"VaaniPlus - English-Hindi Speech Translation". Use a clean white background,
subtle navy and teal accents, clear readable labels, simple professional
icons, and left-to-right data flow. Do not invent components or display secrets.

Show these zones and connections:

1. USER AND BROWSER
   - User signs in or registers, selects English-to-Hindi or Hindi-to-English,
     types text or records audio, views the transcript and translation, plays
     generated speech, and views recent history.
   - Browser UI is built with Vite and vanilla TypeScript.
   - The browser captures microphone audio only after the user starts recording.
   - The browser stores the bearer token in sessionStorage.

2. FRONTEND DEVELOPMENT SERVER
   - Vite runs on 127.0.0.1:5173.
   - Requests under /api are proxied to the FastAPI backend at 127.0.0.1:8000.

3. FASTAPI BACKEND
   - API routes: authentication, typed translation, speech-to-text,
     speech-to-speech translation, text-to-speech, and conversion history.
   - Authentication validates bearer JWTs and hashes passwords.
   - Services orchestrate provider calls and return controlled API responses.
   - Typed translation calls the translation provider; the frontend then makes
     a separate text-to-speech request.
   - Speech translation follows STT -> language check -> translation -> TTS.
   - When an authenticated user completes a text or speech translation, save
     the conversion and keep only that user's five newest records.

4. PROVIDER AND MODEL LAYER
   - Provider interfaces: STTProvider, TranslationProvider, TTSProvider.
   - Mock mode uses fake providers for deterministic development/testing.
   - Real mode uses Faster-Whisper for speech-to-text, MarianMT for translation,
     and Kokoro for speech synthesis.
   - Real model weights are cached locally and may be downloaded from configured
     model hosts on first use.

5. DATABASE AND DEPLOYMENT
   - PostgreSQL 16 runs in a Docker Compose container with a persistent volume.
   - The users table stores account email and password hash.
   - The conversions table stores direction, source text, translated text,
     timestamp, and a foreign key to its user.
   - One user has zero or more conversion records; only the newest five are kept.
   - Show the Vite frontend and FastAPI backend as local host processes, and
     PostgreSQL as the Docker container. Do not imply that model inference runs
     in PostgreSQL or that the backend is inside Docker.

Make the main speech path visually prominent. Use solid arrows for request/data
flow and dashed arrows for optional authentication, mock/real provider choice,
and first-use model downloads. Group related boxes and use concise labels.

  +id: int

  +transcribe(audio, language): STTResult

  +transcript: str

  +translate(source_text, direction): str | TranslationResult
}

class TranslationResult {
  +translated_text: str
  +source_language: str
  +target_language: str
}

interface TTSProvider {
  +synthesize(text, target_language): TTSAudio
}

class SpeechTranslationResult {
  +transcript: str
  +translated_text: str
  +source_language: str
  +target_language: str
  +direction: str
  +audio: bytes | Path
  +content_type: str
}

User "1" -- "0..5" Conversion : owns recent history\n(user_id foreign key)
AuthRequest ..> TokenResponse : registration/login
TokenResponse *-- UserResponse
STTProvider ..> STTResult : returns
TranslationProvider ..> TranslationResult : returns
@enduml

Note: The database can store at most five recent Conversion rows per user.
The Conversion-to-User foreign key cascades when a user is deleted. Provider
interfaces are Python protocols; concrete providers are selected by runtime
configuration. SpeechTranslationResult carries text fields copied from the STT
and translation results; it does not hold those result objects.
